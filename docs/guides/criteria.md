# Define and publish review criteria

Review criteria, also called a **rubric**, describe the judgments reviewers should make and the evidence needed to support them. Every program begins with five starter criteria. Review them against your team's service standards before publishing.

## Make each criterion assessable

In **Program settings → Review criteria**, inspect:

| Field | How to use it |
| --- | --- |
| Section and title | Group related criteria and name the specific behavior being assessed. |
| Instructions | Say what the reviewer should look for and what falls outside the criterion. |
| Evidence guidance | Describe the source material that can establish an outcome. |
| Response scale | Choose **Pass / Fail** or an anchored **1–5** rating scale. |
| Rating anchors | Describe what each rating means so reviewers use the same standard. |
| Weight | Set the criterion's relative importance. |
| Counts toward score | Decide whether it contributes to the numerical score. |

For example, a communication criterion might ask whether the agent explained the next action in language the requester could understand. Its guidance should say which request messages establish that behavior and when it is not applicable. This is an illustrative criterion, not a claim about a specific team's policy.

## Save, preview, then publish

1. Edit the draft and choose **Save draft rubric**.
2. Choose **Preview publication**.
3. Check the instructions, response scales, evidence requirements, and scoring choices.
4. Confirm publication when the criteria are ready for use.

An unsaved edit is not a published change. Publication creates a preserved version for future work; existing periods and cases keep their assigned versions.

You can copy a published rubric version from the same program into its editable draft. Inspect the replacement preview before confirming it. Copying does not publish the draft.

## Improve the standard without rewriting history

Use [calibration](calibration.md) to find ambiguous instructions. Clarify the draft and publish a new version for later reviews. Compare results by rubric version so a changed standard is not mistaken for a change in service quality.
